# 말로일기 · 내 말투를 살리는 음성 일기

- 작성자: 양진석
- 작성일: 2026-10-29
- 제품: 말로일기 — 글쓰기가 번거로운 사람이 말로 하루를 기록하는 일기 앱
- 선택 기능: 자유롭게 말한 내용을 내 말투를 살려 정리하고, 직접 확인·수정한 뒤 저장하기
- 작성 방법: `/grill-me` 인터뷰에서 결정한 내용을 바탕으로 작성
- 프로토타입: `prototypes/양진석/`
- WhyTree: [양진석의 WhyTree](../whytree/양진석.md)

## 1. 누구를 위한 기능이며, 언제 문제가 생기는가

일기를 쓰고 싶지만 직접 타이핑하고 생각을 정돈된 문장으로 만드는 일이 번거로워, 하루 이틀 기록하다가 그만두는 사람을 위한 기능이다. 사용자는 휴대폰으로 기록하고 다시 읽는다.

하루를 마무리하거나 기억하고 싶은 일이 생겼을 때, 남길 생각은 있어도 글을 쓰기 시작하는 데 부담을 느낀다. 기록하지 않으면 그날의 기분과 기억이 흐려지고, 나중에 자신의 발자국과 변화를 돌아볼 자료도 남지 않는다.

이 기능은 사용자가 말할 순서나 문장을 준비하지 않고 자유롭게 이야기하도록 돕는다. AI는 사용자를 대신해 경험이나 감정을 만들어내지 않고, 실제로 말한 내용과 말투를 보존해 읽을 수 있는 초안을 만든다.

## 2. WhyTree와의 연결

팀 저장소의 WhyTree 경로는 `docs/whytree/양진석.md`이다. 명세서와 같은 개인 식별자 `양진석`을 사용한다.

이 기능이 직접 지원하는 노드는 다음 두 가지다.

- **타이핑 대신 자유롭게 말하기**
- **두서없는 이야기를 일기로 정리하기**

상위 목적과의 연결은 다음과 같다. 문구는 WhyTree와 동일하다.

- 나를 이해하고 성장하기
    - 나의 발자국과 변화를 돌아보기
        - 하루의 기분과 기억을 보존하기
            - 나의 하루를 기록하고 정리하기
                - 기록에 드는 수고 줄이기
                    - 타이핑 대신 자유롭게 말하기
                    - 두서없는 이야기를 일기로 정리하기
                - 기록을 이어가는 부담 줄이기
                    - 30초 정도의 짧은 기록 남기기

‘30초’는 짧게 남겨도 충분하다는 사용 방향이다. 최소 녹음 시간이나 전체 일기의 최대 길이가 아니다. 녹음은 한 구간당 최대 3분이며, 전체 기록의 종료는 사용자가 결정한다.

‘가끔 예전 기록 꺼내 보기’는 P1, 여러 기록을 비교해 변화를 돌아보는 기능은 P2로 둔다. 저장된 일기를 사용자가 직접 다시 여는 기능은 P0에 포함한다.

## 3. 사용자가 하는 일 — P0 사용자 흐름

1. 휴대폰에서 서비스를 열고 **말로 일기 쓰기**를 누른다. 처음 사용하는 경우 마이크 권한을 허용한다.
2. **녹음 시작**을 누르고 자유롭게 이야기한다. 화면에는 녹음 중인지와 이번 구간의 경과 시간을 표시한다.
3. 사용자는 3분 전에 **이 구간 멈추기**를 누를 수 있다. 3분에 도달하면 이번 구간만 자동으로 멈추고, 종료음과 화면 안내로 알린다. 이때 일기를 자동 저장하거나 전체 기록을 종료하지 않는다.
4. 각 구간의 음성을 텍스트로 변환한다. 성공한 구간의 텍스트와 처리 상태를 확인할 수 있다. 실제 결과가 없는 구간에 글을 추측해서 채우지 않는다.
5. 더 이야기하고 싶으면 **이어서 녹음**을 누른다. 최대 3분짜리 새 구간이 같은 일기에 추가된다. 구간 번호와 녹음 순서를 유지하며, 변환 완료 순서가 달라도 본문 순서를 바꾸지 않는다.
6. 인식 오류나 변환 실패가 있으면 확보된 텍스트를 보고 판단한다. **이 구간 다시 녹음**은 선택한 구간을 대체하고, **이어서 녹음**은 기존 구간 뒤에 추가한다. 다른 구간은 유지한다. 대체 녹음의 변환이 성공하기 전에는 기존 텍스트를 지우지 않는다.
7. 사용자가 **녹음 마치고 초안 확인**을 누르면 전체 녹음을 마무리한다. 아직 변환 중인 구간은 상태를 표시하고, 완료를 기다린 뒤 녹음 순서대로 합친다. 실패 구간이 있으면 해당 위치를 알리고, 다시 녹음할지 확보된 내용으로 진행할지 사용자가 정한다.
8. AI가 합쳐진 텍스트에서 머뭇거림을 정리하고 문장부호와 문단을 다듬는다. 말투와 생각은 보존한다.
9. 사용자가 초안을 읽고 사람 이름, 명사, 인식 오류 등을 직접 수정한다. 사용자가 고친 내용을 AI가 다시 자동으로 덮어쓰지 않는다.
10. **저장**을 누르면 날짜와 최종 텍스트를 휴대폰에 저장하고 성공 여부를 표시한다. 저장 목록에서 다시 열어 읽을 수 있다. 새 P0 녹음 원본은 보관하거나 재생하지 않는다. 이전 버전에서 보관한 음성의 재생 기능은 유지한다.

전체 일기에 별도의 3분 제한이나 정해진 구간 수 제한을 두지 않는다. 긴 녹음의 기술적 한계가 구현 중 발견되면, 내용 누락이나 임의 요약으로 숨기지 않고 명세서를 먼저 수정한다.

## 4. 기능별 우선순위

| ID | 우선순위 | 항목 | 완료 조건 |
|---|---|---|---|
| F01 | P0 | 휴대폰 중심 화면과 마이크 권한 처리 | 휴대폰에서 녹음·확인·수정·저장이 가능하고, 마이크를 사용할 수 없으면 해결 안내를 보여준다. |
| F02 | P0 | 녹음 시작·수동 정지·3분 자동 정지 | 3분에 해당 구간만 멈추고 종료음과 화면 안내를 제공한다. |
| F03 | P0 | 같은 일기에 추가 녹음 | 다시 누를 때마다 새 구간을 추가하고 순서를 유지한다. 전체 종료는 사용자가 선택한다. |
| F04 | P0 | 음성 인식 | 각 구간을 실제 AI로 받아쓰고, 성공·처리 중·실패 상태를 구분한다. |
| F05 | P0 | 내 말투를 보존한 문장 정리 | 내용과 말투를 유지하며 사고 중의 군더더기 발성, 문장부호와 문단만 정리한다. |
| F06 | P0 | 초안 확인과 직접 수정 | 이름·명사 등 본문을 직접 수정하고, 수정한 최종 본문을 저장한다. |
| F07 | P0 | 텍스트 저장과 직접 다시 열기 | 같은 휴대폰·브라우저에서 저장 목록과 일기 본문을 다시 읽을 수 있다. |
| F08 | P0 | 구간 다시 녹음·이어서 녹음 | 사용자가 두 동작을 구분해 선택하고, 성공한 기존 구간과 편집 내용이 뜻하지 않게 사라지지 않는다. |
| F09 | P0 | AI·네트워크·저장 실패 처리 | 확보된 글을 보존하고 현재 상태와 다음 행동을 표시한다. 실패를 성공으로 표시하지 않는다. |
| F10 | P0 | 음성 비보관과 API 키 보호 | 음성은 처리용으로만 사용하고 앱의 영구 저장소·로그에 남기지 않는다. API 키는 서버 환경변수로만 사용한다. |
| F11 | P1 | 예전 일기 자동으로 꺼내 보여주기 | 사용자가 목록에서 고르지 않아도 가끔 과거 기록을 보여준다. P0 완성 후 진행한다. |
| F12 | P2 | 여러 기록에서 나의 변화 돌아보기 | 여러 시점의 기록을 비교해 돌아보는 기능. 구체적인 동작은 후속 명세서에서 정한다. |

P0는 반드시 구현한다. P1은 시간이 남으면 구현하며, P2는 이번 과제에서 구현하지 않는다.

## 5. AI 모델과 문장 정리 기준 — P0

### 사용할 모델

| 단계 | 모델 | 역할 | 실패 시 |
|---|---|---|---|
| 음성 인식 | OpenAI `gpt-transcribe` | `/v1/audio/transcriptions`로 녹음 구간을 한국어 텍스트로 변환 | 성공한 다른 구간의 글을 유지한다. 실패 구간을 표시하고 사람이 다시 녹음하거나 이어서 녹음하도록 한다. |
| 문장 정리 | OpenAI `gpt-6-luna` | `/v1/responses`로 받아쓴 텍스트를 최소한으로 정리 | 받아쓴 텍스트를 그대로 편집기에 제공하고, 정리 실패를 표시한다. 사용자가 직접 수정해 저장하거나 정리만 다시 요청할 수 있다. |

위 모델은 2026-10-29 공식 문서에서 확인한 선택이다. 2026-10-29 기존 사이트에서 합성 음성과 임시 예제 텍스트로 두 모델의 실제 API 호출을 확인했다. 모델을 바꾸어야 한다면 명세서의 모델명과 실패 처리부터 수정하며, 다른 모델로 조용히 대체하지 않는다.

음성 처리와 텍스트 정리는 서로 다른 단계다. 텍스트 모델에 오디오를 직접 보내는 것으로 구현하지 않는다. 모델 선택 근거: [GPT-Transcribe](https://developers.openai.com/api/docs/models/gpt-transcribe), [음성 인식 가이드](https://developers.openai.com/api/docs/guides/speech-to-text), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).

### 정리 규칙

- 반말·존댓말, 문장 끝의 습관, 사투리, 감정 표현과 의미 있는 반복을 최대한 유지한다.
- 생각하느라 내는 ‘음…’, ‘어…’ 같은 발성은 의미 없는 머뭇거림일 때만 제거한다. ‘아, 진짜 좋았어’처럼 감정이나 의미가 있는 표현은 일괄 삭제하지 않는다.
- 의미를 바꾸지 않는 범위에서 문장부호, 띄어쓰기, 문단을 정리한다.
- 사람 이름·고유명사를 더 그럴듯한 이름으로 추측해 바꾸지 않는다. 사용자가 초안에서 확인·수정한다.
- 말하지 않은 사건, 이유, 감정, 교훈을 추가하지 않는다. 내용을 요약해서 중요한 경험을 빼지 않는다.
- 사용자의 일기 내용을 모델에 대한 지시로 실행하지 않고, 정리할 원문으로만 취급한다.
- 사용자가 직접 고친 초안을 새 AI 결과로 자동 덮어쓰지 않는다.

예시 입력:

> 음… 오늘 민수랑 밥 먹었는데, 진짜 오랜만에 편했어. 어… 이런 시간이 나한테 필요했나 봐.

허용되는 정리:

> 오늘 민수랑 밥 먹었는데, 진짜 오랜만에 편했어. 이런 시간이 나한테 필요했나 봐.

피해야 할 정리:

> 오늘 친구와의 만남을 통해 인간관계의 소중함을 깨달았다.

마지막 예시는 사용자가 말하지 않은 교훈을 추가하고 말투를 바꾸므로 요구사항에 맞지 않는다.

## 6. 오류 상황에서의 동작 — P0

| 상황 | 반드시 지킬 동작 |
|---|---|
| 마이크 권한 거절·사용 불가 | 녹음 중인 것처럼 표시하지 않는다. 권한이나 실행 환경을 확인하도록 안내한다. |
| 음성 인식 실패 | 실제로 반환받은 텍스트만 보여준다. 실패 구간에 결과가 없으면 ‘이 구간은 변환된 내용이 없습니다’라고 알린다. 다른 구간의 글은 유지한다. |
| 사용자가 다시 녹음 선택 | 선택한 구간의 대체 녹음을 만든다. 대체 변환까지 실패하면 기존 텍스트를 유지한다. |
| 사용자가 이어서 녹음 선택 | 기존 구간을 지우지 않고 새 구간을 마지막에 추가한다. |
| AI 문장 정리 실패 | 받아쓴 글을 편집 가능한 상태로 남긴다. ‘정리 완료’로 표시하지 않는다. |
| 무음·빈 입력 | 일기 내용을 생성해 채우지 않는다. 다시 녹음하도록 안내한다. 빈 본문은 저장하지 않는다. |
| 휴대폰 저장 실패 | 편집 중인 글을 화면에 남기고 저장 실패를 알린다. 저장된 것으로 처리하지 않는다. |
| 화면 이탈·녹음 중단 | 계속 녹음되고 있다고 가정하지 않는다. 중단을 감지하면 상태를 알리고, 확보된 텍스트는 현재 화면에서 유지한다. |

음성 변환 실패 후 원래 녹음을 보관해 자동 재전송하는 방식을 기본 흐름으로 삼지 않는다. 사용자가 결과를 보고 다시 녹음하거나 이어서 녹음한다는 인터뷰 결정을 따른다.

## 7. 저장과 실행 환경 — P0 구현 기준

- 구현 방식은 휴대폰 브라우저에서 여는 웹앱으로 잡는다. 사용자의 핵심 요구는 휴대폰에서 편하게 사용하는 것이며, 앱 설치 자체는 필수가 아니다.
- 앱 자체 계정 기능 없이 같은 휴대폰의 같은 브라우저에서 사용한다. 기존 Sites 테스트 주소는 본인 전용이며 접속 시 ChatGPT 인증이 필요하다. 이 접근 제한은 그대로 유지한다. 최종 텍스트와 날짜는 브라우저의 IndexedDB에 저장한다. 다른 기기와 동기화하지 않는다.
- 일기의 날짜는 새 일기를 시작한 시점의 휴대폰 현지 날짜를 기본으로 한다. 추가 녹음은 같은 일기에 속한다.
- 자동 클라우드 백업·기기 간 동기화는 이번 P0 범위 밖이다. 기존 수동 백업 파일 내보내기·가져오기는 유지한다. 브라우저 데이터를 지우거나 기기를 바꾸기 전에 사용자가 백업 파일을 따로 보관해야 한다. 저장 전 초안의 새로고침 후 복구도 이번 P0에서 보장하지 않는다.
- 음성은 녹음·전송·변환에 필요한 동안만 메모리나 처리용 임시 데이터로 사용한다. 처리 성공·실패·취소 시 앱이 가진 해당 오디오 자원을 해제한다. 새 P0 녹음에 대한 재생 목록, 오디오 파일 저장, 서버 영구 보관은 만들지 않는다. 기존 보관 음성·사진과 수동 백업 기능은 유지한다.
- AI 호출에는 인터넷과 서버 측 API 처리가 필요하다. API 키를 브라우저 코드, 저장소, 사용자 일기에 넣지 않는다. 서버 로그에 오디오나 일기 본문을 남기지 않는다.
- Responses API는 `store: false`로 호출한다. 앱의 비보관 설계와 AI 제공자의 데이터 정책은 별개다. OpenAI 공식 정책상 음성 인식 엔드포인트의 보관 항목은 ‘없음’으로 안내되지만, 텍스트 처리에는 기본적으로 최대 30일의 악용 방지 로그 정책 등이 적용될 수 있다. `store: false`를 모든 제공자 기록의 즉시 삭제로 설명하지 않는다. [공식 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)
- 실제 휴대폰 테스트는 HTTPS 주소에서 마이크 권한을 허용한 상태로 진행한다. 웹 마이크 접근의 보안 연결·권한 요건은 [MDN getUserMedia 문서](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)를 따른다.
- 첫 버전은 녹음 화면을 열어둔 상태를 대상으로 한다. 종료음은 미디어 소리가 켜진 실제 휴대폰에서 검사한다. 소리를 들을 수 없는 상황에도 종료 상태를 알 수 있도록 화면 표시를 함께 제공한다. 백그라운드·잠금 화면의 지속 녹음은 P0 범위 밖이다.

- **P1로 미룸:** 예전 기록을 앱이 자동으로 골라 보여주기.

통과 기준: 짧은 녹음을 허용하고, 사용자 수정 내용까지 동일하게 다시 읽을 수 있다. 목소리 파일이나 재생 항목은 없다. 관련 항목: F01, F04~F07, F10.

## 12. 구현 및 재현 기준

- 제출 프로토타입은 기존 앱의 AI Worker를 재사용하고, 모바일 웹 작성 흐름을 독립 실행 가능한 파일로 분리한다. 새 일기는 기존 일기 IndexedDB에 최종 텍스트·날짜를 기록한다. 사진은 저장 후 사용자가 선택해 추가한다. 이전 P0 저장소의 글은 기존 기록을 덮어쓰지 않고 연결하며, 과거 음성·사진은 보존한다.
- 홈의 검사 모드 `/?selftest=1`에서 말로 일기 쓰기를 누르면 `/hw6/index.html?compose=1&test=1`로 연결된다. 이 작성 검사 화면에는 다음 음성 인식 실패와 문장 정리 실패를 각각 재현하는 버튼이 있다. 가짜 성공 응답을 만들지 않고 해당 단계의 실패 처리만 재현한다.
- 텍스트 정리는 전체 성공 후 편집기에 한 번 반영한다. 재정리는 사용자가 편집한 현재 글을 대상으로 하며 처리 중 편집을 잠시 잠근다.
- 처리 중에는 새 구간 녹음을 시작할 수 있지만 API 요청은 순서대로 보내 기존 서버의 동시 요청 제한과 충돌하지 않게 한다.

초기 P0 자동 검사 16개와 기존 앱 회귀 검사 86개가 통과했고, 사진·검색 통합 후의 검사 결과는 검증 기록에 별도로 남긴다. 실제 음성 인식·문장 정리 및 실패 시 글 보존을 확인했다. 자세한 결과와 미확인 항목은 prototypes/양진석/VALIDATION.md에 기록했다. 검사 모드는 개인 일기와 별도 저장소를 사용한다.

## 13. 기존 제품 기능 유지 — 2026-10-29 사용자 수정

P0는 새로 완성할 음성 작성 기능의 최소 범위이며, 기존 제품의 사진 첨부·검색·설정을 없애라는 의미가 아니다. 기존 첫 화면(내 일기·기억 찾기·설정)을 유지하고 말로 일기 쓰기에서 P0 작성 화면으로 연결한다.

- F07/P0 호환성: 확인 후 저장한 새 일기도 기존 일기 저장소에 들어가 목록·검색·상세·사진 첨부·백업 기능에서 사용할 수 있어야 한다.
- 저장 후 기존 상세 화면에서 사진을 선택해 추가하고, 검색 결과에서 같은 일기와 사진을 다시 열 수 있다. 사진은 기기에 저장하며 사진 분석을 위해 AI에 자동 전송하지 않는다.
- 앞서 분리한 P0 저장소의 일기는 기존 기록을 덮어쓰지 않는 방식으로 연결한다. 완료 표시를 남겨 다시 열 때 중복되거나 삭제한 일기가 되살아나지 않게 한다.
- 과거 음성·사진은 보존한다. 새 P0 녹음은 여전히 음성을 영구 저장하지 않고 사용자가 확인한 글만 저장한다. 사진은 사용자가 선택했을 때 추가한다.
- 검사 기록은 기존 앱의 검사 전용 저장소와 연결하고 개인 기록과 섞지 않는다.
- 수동 검사 1에 저장 후 사진 추가 → 기억 찾기에서 본문 단어 검색 → 해당 일기와 사진 재확인을 추가한다. 2026-10-29 본인 휴대폰 Safari에서 실행 완료·통과했다고 보고했다.

변경 이유: 기존 제품을 업그레이드해야 했지만 P0 화면을 첫 화면으로 대체해 사진·검색 기능이 빠진 것처럼 보였다. 사용자 지적에 따라 기존 제품 화면을 복원하고 작성 기능만 통합한다.
