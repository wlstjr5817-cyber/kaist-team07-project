# 말로일기 · 일기 뒤 AI 후속 질문

- 이름: 우승현

- 코드 위치: `prototypes/우승현/`
- WhyTree: [docs/whytree/우승현.md](../whytree/우승현.md)

## 1. 누구를 위한 것이고, 문제는 언제 나타나는가

- 대상: 일기를 써 보다가 여러 번 그만둔 직장인과 자영업자. 글로 쓰기보다 말하기가 편한 사람
- 문제가 나타나는 순간: 피곤한 저녁에 하루를 말로 남긴 직후. 그날 있었던 일은 기록되지만, 그때 느낀 감정과 생각은 따로 꺼내 보지 않고 지나간다
- 팀의 더 깊은 필요: "내 생각과 감정을 더 잘 이해하고 싶다". AI가 사용자와 주고받으며 감정에 대해 한 번 더 생각하게 돕는다

## 2. 사용자가 하는 일 (단계별)

1. 오늘 일기를 말로 남긴다. 받아쓴 글이 입력창에 나오고, 직접 고칠 수 있다. 말하기가 안 되면 텍스트로 입력한다
2. 일기를 마치면 AI가 감정과 생각에 관한 짧은 질문을 **한 번에 하나씩** 한다. 최대 3턴이다
3. 각 질문에 말 또는 텍스트로 답한다. 다음 질문은 앞 답변을 보고 정한다
4. 대화가 끝나면 **원래 일기 원문**(AI가 고쳐 쓰지 않음)과 **질문·답변 기록**을 함께 본다

## 3. 어느 WhyTree 노드를 위한 것인가

- **대화형 챗봇** `[점선 상자]` → 다른 사람과 대화하기 → 회고 → 나의 생각과 감정 이해하기
- 질문은 사실이나 감각보다 **감정과 생각**을 묻는다
- 처음에는 `생생하게 기록하기`를 위한 기능으로 구상했다. 하지만 질문의 목적이 장면을 되살리는 것보다 감정을 이해하는 것에 가깝고, 팀 문제 정의("AI가 감정에 대해 더 생각하게 돕는다")와도 맞아서 `대화형 챗봇`으로 정했다

## 4. 범위 밖

- 조언, 진단, 위로하는 말. AI는 묻기만 한다
- 전문 심리 상담 기능. 트리에 있는 아이디어일 뿐 넣을지는 정하지 않았다
- 실제 LLM 호출 (오늘은 API 키가 없음)
- 지난 일기 보기와 관리 (팀원 담당)
- 저장(새로고침하면 사라짐), 음성으로 틀린 부분 고치기, 로그인, 위기 발언 대응, 모바일 앱

## 6. AI 모델과 실패 시 동작

- 질문은 실제 LLM이 아니라 **미리 써 둔 질문**으로 만든다
- 질문 고르는 규칙
  - 질문 1: 일기에서 감정 단어(속상, 짜증, 좋았, 피곤 등 30개 안팎)를 찾아 그 순간을 짚는다. 예: "'속상'하다고 하셨는데, 언제 가장 그랬어요?" 못 찾으면 "오늘 가장 기억에 남는 순간은 언제였어요?"
  - 질문 2: 질문 1의 답에 감정 단어가 있으면 "왜 그런 기분이 들었을까요?", 없으면 "그때 기분을 한 단어로 하면요?"
  - 질문 3: "지금 돌아보면 어떤 생각이 들어요?"
- 말투: 존댓말 한 문장
- 음성 인식: Chrome 내장 Web Speech API. 브라우저가 지원하지 않거나(Safari 등) 마이크를 거부하면 마이크 버튼을 숨기고 텍스트 입력만 쓴다
- P1 LLM: Claude(`claude-haiku-5-5`). 키는 페이지에서 입력받고 저장소에 넣지 않는다. 호출이 실패하면 위의 미리 써 둔 질문으로 돌아간다

## 7. 손으로 하는 확인

1. Chrome에서 일기를 말로 입력하면 받아쓴 글이 입력창에 나오고, 고칠 수 있다
2. 질문이 하나씩 3개 나온다. 질문 2는 답에 감정 단어가 있을 때와 없을 때 다르게 나온다. 한 번은 말로, 한 번은 텍스트로 답한다
3. 마이크를 거부하거나 Safari에서 열어도 텍스트만으로 끝까지 가서 결과 화면이 나온다

커밋 전에는 `git grep`으로 저장소에 API 키나 `.env`가 없는지 확인한다.
