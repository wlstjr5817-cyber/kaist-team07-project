- 실행 주소: https://malro-diary.jinseokyang.chatgpt.site/

## 실행 방법

Node.js 22 이상에서 이 폴더를 연 뒤 다음을 실행한다. 외부 패키지 설치는 필요 없다.

```sh
npm start
```

표시되는 localhost 주소에서 화면과 오류 동작을 확인할 수 있다. 실제 AI 처리에는 `.env.example`을 참고해 로컬 `.env`에 본인의 API 키를 설정한다. 키를 채팅이나 GitHub에 올리지 않는다. 배포된 기존 사이트에는 이미 서버 Secret이 설정되어 있으며 이 저장소로 복사하지 않는다.

휴대폰 실기기 검사는 위 HTTPS 배포 주소에서 실행한다. 휴대폰의 localhost는 개발 PC 주소가 아니다. 개발 서버는 PC의 루프백 주소에만 바인딩하며 외부 공개용 서버가 아니다.

```sh
npm ci
npm test
```

`npm ci`는 검사 전용 `fake-indexeddb`를 설치한다. 앱 실행 자체에는 외부 패키지가 필요 없다.

## 구현한 P0

| 명세 항목 | 구현 |
|---|---|
| F01 | 모바일 화면, 마이크 권한·HTTPS·브라우저 지원 오류 안내 |
| F02 | 자유로운 짧은 녹음, 수동 정지, 180초 구간 정지, 종료음·화면 표시 |
| F03 | 최대 3분 구간을 같은 일기에 계속 추가, 사용자만 전체 종료 결정 |
| F04 | `gpt-transcribe` 실제 음성 변환, 처리·성공·실패 상태 |
| F05 | `gpt-6-luna`로 말투와 생각을 보존하고 머뭇거림만 정리 |
| F06 | 저장 전 초안 편집, 원문 보기, 사용자 수정 보호 |
| F07 | 최종 본문·날짜만 IndexedDB 저장, 목록·상세에서 다시 열기 |
| F08 | 선택 구간 대체와 마지막에 추가를 구분, 대체 실패 시 기존 글 보존 |
| F09 | 인식·AI 정리·저장 실패 안내와 글 보존, 빈 일기 저장 차단 |
| F10 | 음성 메모리 처리 후 해제, 음성 영구 저장·재생 없음, 서버 API 키 |

`public/hw6/`가 제출 화면이며 `worker/`는 기존 앱에서 가져와 수정한 AI 서버 모듈이다. `server.mjs`는 같은 모듈을 실행하는 로컬 개발 서버다. 전체 기존 Expo 앱과 개인 기록은 제출 폴더에 복사하지 않았다. 배포된 사이트의 첫 화면은 이 P0 화면이며 기존 기록은 이전 보관함에서 유지된다. 이전 보관함의 과거 기능은 이번 P0 평가 범위가 아니다.

## 검사 방법과 한계

- `?test=1`에서 다음 음성 인식 실패, 다음 문장 정리 실패, 다음 기기 저장 실패를 선택해 각각 재현한다. 실패 표시를 해제하면 다음 요청은 정상 경로를 사용한다.
- 검사 모드는 별도 IndexedDB를 사용하므로 개인 일기 목록에 검사 기록이 섞이지 않는다. 검사한 일기를 다시 읽으려면 `?test=1`을 유지한다.
- 합성 음성 버튼은 기존 앱에서 만든 공개 예제 WAV를 실제 API에 보낸다. 성공을 흉내 내는 기능이 아니다. 마이크 권한·실제 3분·아이폰 종료음은 별도로 검사해야 한다.
- 3분 정지는 타이머와 브라우저 녹음 이벤트에 의존한다. 앱 화면을 열어두고 미디어 소리를 켠 상태가 P0 대상이다. 화면을 감추면 중단 안내와 확보된 음성의 처리를 시도한다. 브라우저 강제 종료 시 저장 전 내용의 복구는 보장하지 않는다.
- AI 결과의 정확성을 보장하지 않는다. 이름·명사·말투와 생각 보존은 저장 전 사용자가 확인한다.
- 긴 글은 8,000자 이하씩 정리하며, 한 부분이라도 실패하면 전체 원문을 편집기에 보존한다.
- 저장된 기록은 같은 브라우저에만 남는다. 클라우드 동기화·백업은 P0 범위 밖이다.
- OpenAI 제공자의 보관 정책은 앱의 음성 비보관 정책과 별개다. Responses 호출에는 `store:false`를 사용한다.

자동 검사 결과와 본인 수동 검사 결과는 [VALIDATION.md](VALIDATION.md)에 구분해 기록한다. 본인 수동 검사 3개는 명세서에 있는 절차대로 직접 실행해야 한다.
